1. 产品目标与用词
=================
PACE 是 sport dating / 运动生活方式交友产品。帮助有共同运动兴趣的人认识
活动搭子、潜在伴侣，或同时成为两者的人。运动是建立共同生活方式与相处
机会的语境，不是成绩排行榜或健身训练管理工具，也不强迫每次相识都约会。

核心闭环：真实资料 → 发现合适的人 → 双方真实喜欢 → 匹配 → 聊天 →
安排一起运动/见面。Plus 可以提供匹配前的结构化邀约机会。
扩展闭环：已连接用户分享动态；附近公开活动帮助自然认识与相处。

内容与文案约束：
- 优先表达认识、兴趣、连接、相处、共同安排；保持简短、自然、成熟。
- 避免所有页面都像训练软件：不要反复讲成绩、竞技、强度、训练任务。
- 同样避免过度暧昧、催促约会、承诺一定配对；普通活动搭子也属于目标用户。
- 使用熟悉名称：Matches、Chat、Profile、Settings & account。
- 数据字段用稳定 ID；中文/英文名称只是展示。术语解释见 CONTEXT.md。
- 当前词典包括中、英、法、西、德，但不代表每个流程都已完整本地化。

2. 已确立的产品规则
===================
2.1 发现与匹配
- 距离筛选属于基础功能，发现页一次点击可进入；不能设为会员专享。
- 没有符合距离/偏好的人就诚实显示空状态，由用户选择调整筛选。
  不擅自扩大半径、不补假人、不加没有真实服务支持的等待名单按钮。
- Like、Match、未读、喜欢人数必须来自真实记录。单方 Like 不能宣称匹配。
- 正常 match 基于真实双向 Like；接受陌生邀约是否建立关系尚待决定。
- 运动水平用于解释生活方式，不作为人格价值判断；不要只凭外貌或成绩。

2.2 免费与 Plus
- 匹配、与已匹配用户聊天、匹配内邀约、距离筛选、浏览和参加公开活动免费。
- 查看完整喜欢我的人、向未匹配的人直接邀约、创建公开活动属于 Plus。
- 创建公开活动还需要可信的主持人认证。主持人计入容量，不能直接退出
  自己的活动；取消活动需要独立流程。
- 邀约发送只创建 pending，不能自动创建 match、会话或假装对方已同意。
- 每次提交重新检查有效订阅、匹配关系、双方拉黑、用户/活动状态与额度。
  打开表单时的一次检查不能替代提交时的服务端鉴权。
- Plus 不得绕过举报、封禁、拉黑、防骚扰、容量和隐私限制。
- 取消续费后，已付款有效期间继续保留权益；到期/撤销后拒绝新的会员操作。
- 账单入口在设置一级。提供恢复购买和系统订阅管理，不设置挽留障碍。
  关闭 Apple 管理窗口不等于取消成功；以可信交易状态为准。
- 价格、币种、周期来自真实 StoreKit 产品配置，不在 UI 编造价格或成功支付。
- 本地预览默认免费，没有购买桥时购买/恢复不可用；localStorage 不能授予 Plus。
- 产品规格要求取消订阅或删除账号后停止营销；按服务端已确认状态执行，
  事务通知与营销分开，营销需明确 opt-in。

2.3 信任与资料
- 最多 6 张个人照片，第一张用于主要资料展示；注意脸部裁切与焦点。
- 身高、族裔可选择是否公开；隐藏时公共 API 也必须不返回隐藏值。
- 精确生日、住址、运动轨迹不作为公开资料；公开距离要适当粗化。
- 自拍活体认证是旧规格的必经步骤，当前实现未真正执行；不得展示假认证
  并当作已完成验证。正式上线的门槛/供应商/失败处理需要确认和接入。
- Strava / Apple Health / Garmin 为可选方向，不是目前真实接通的功能。
- 简介无最低字数、运动不限数量是旧规格要求；当前注册存在相反限制，
  属于待归一的实现差异，不因代码如此就视为已批准的新规则。
- 动态原则上对已连接的人可见；头像/姓名进入该人的既有 Profile 页面。
- 账号删除必须是真实撤销会话、停止发现/营销并处理数据，不是仅弹提示。

3. 视觉与交互决策：保留最终选择，别退回旧草稿
=============================================
已确认方向：黑色/炭黑的柔和渐变与细颗粒质感，克制的暖灰文字，主色采用
较暗的黄绿色。当前 tokens：--lime #B4CF42，--canvas #101110，
--panel #171A17，--panel-2 #20231F，--paper #F4F5EF，--muted #969C94。
辅助色 aqua #00DCCE、orange #FF704F 只在有意义的地方使用。
早期“荧光薄荷/跑道蓝黑”文字不是最新配色依据。

具体已讨论且需保持的变化：
- 欢迎页参考深色质感背景、大字、简洁 PACE 标识；照片信息仍是发现页主角。
- Google 与 Apple 登录按钮并排，深灰底、细边框，标识直接放在按钮内；
  不再套难看的独立大黑框。按钮文案与图标间距要稳定。
- 编辑资料采用干净的分隔与留白，避免厚重卡片层层套叠。
- 深色表单展开后的选项也要清晰可读，不能白底浅字；需验证系统原生控件。
- 发现卡片底部原彩色缎带背景已改成炭黑质感，不能被旧 CSS 覆盖回来。
- 三个运动项目最终选择为一条横向等分排列，图标在上、名称在下；
  之前的左侧纵排、左上到右下阶梯排已经被后续指令替代。
- 每周活动次数是独立摘要，与三项运动保持清晰分隔，不能挤占名称。
- 活动类别用统一折叠/搜索选择器容纳完整项目，目前目录为 43 种运动。
- Chat / Profile 是同一人物页面的两个分区；动态头像/姓名默认进入 Profile，
  返回仍回到来源动态。本人动态进入自己的资料，不能误套 Maya 的年龄/照片。
- 去掉 Chat 顶部及 Profile 内的 “Matched on PACE”；去掉 Photos 下长说明；
  去掉动态卡片底部独立 Chat 按钮。
- 登录后返回设备：加载页检查会话后直接进入发现卡片，避免每次重新问登录。
  无效会话回欢迎页；网络失败提供重试，不假装用户已退出。
- 初次显示应柔和，减少突然跳出；应用外壳使用透明度过渡，底部导航位置稳定。
  字体/首图加载有限等待；资源失败不能永久卡启动。支持 reduced motion。

4. 当前实现与上线阻断：禁止把演示说成真实功能
===========================================
4.1 已有可复用基础
- HTML/CSS/原生 ES Modules；按 feature 拆文件；本地字体和主要图片。
- 本地与 HTTP repository seam、统一 API client、纯逻辑与契约测试。
- Onboarding、多语言文案、会话恢复加载页、发现筛选/画廊、匹配/聊天页面、
  资料编辑、动态、Plus 界面、活动列表/筛选/详情/本地参加退出。
- Plus/活动/Apple 交易规则的内存 reference service 和 StoreKit 桥接口。
  这些是规则与接缝，不是已部署服务。

4.2 必须正视的缺口（完整证据见两份 2026-09-26 审计）
- 注册密码并未创建真实账号；Google/Apple 入口使用演示身份，缺真实 token
  交换、邮箱验证/恢复、安全账号关联与完整 session 生命周期。
- 本地“记住登录”只保存 30 天版本化 demo marker；不保存账号、资料或会员。
  本地能恢复进入页面，不证明跨设备资料/生产登录已完成。
- Discovery 返回数据主要控制显隐，卡片仍固定 Maya；Like 会演示匹配成功，
  没有真实双向喜欢和唯一 match/conversation 的数据库事务。
- 聊天显示示例问答；发送只追加 DOM，重开即丢失，无真实会话历史/实时服务。
- Chat 内的邀约表单只关窗并提示成功；未保存收件人或邀请。Discovery 的
  direct invite 有 repository seam，但两条路径尚未形成完整统一领域服务。
- 资料启动没有完整读取本人保存信息；注册字段存在未完整持久化的部分。
- 资料/动态使用本地 blob 图片预览；媒体上传 API seam 未完成生产上传闭环。
  动态存在固定作者/客户端认证数据，应改为 session 派生和服务端校验。
- 示例人 ID 存在 maya / user_maya 差异；缺 verified 字段时可能默认显示徽章。
- “自拍已认证”“Garmin 已连接”等为演示状态，不是真实验证/连接结果。
- 删除账号只是本地标记及提示，未撤销 session 或真正清理数据。
- 缺举报、双向拉黑、取消匹配、审核运营闭环及真实消息/邀请通知。
- 无原生 iOS target、真实 StoreKit adapter、Apple JWS verifier、webhook、
  持久订阅账本或 APNs 配置；目前不能承诺 App Store 对接已经完成。
- 全局 HTTP 超时/401处理、错误重试、公共 DTO 隐私、媒体验证仍需完善。
- Onboarding、部分表单/系统文案仍混用英文；tabs 键盘语义、match 弹窗焦点、
  上传限制/取消释放等仍有缺口。全盘检查不等于这些问题已经修复。

B14 隐私删除：撤销 session、停止营销/发现、异步清理、导出、同意与保留策略。
B15 通知：APNs 设备绑定、outbox、重试去重、偏好、隐私、深链接。
B16 运动接入：真实授权/撤销/同步/来源；不实现则去掉误导的已连接状态。
B17 服务运维：HTTPS、密钥、最小权限、日志脱敏、监控告警、备份恢复和回滚。
B18 发布验收：staging 多账号、真机/弱网、Apple Sandbox、隐私条款与商店资料。

重点测试边界：
- 无身份/伪造 actor 不得读写；猜 ID 不得读取他人私聊或隐藏资料。
- 单方 Like 无 match；并发互相 Like 只创建一次；配额不被多设备突破。
- 免费未匹配邀约拒绝且零写入；已匹配免费可发；打开表单后会员过期仍拒绝。
- 同一消息/邀请/交易重试幂等；接受与取消并发只能产生一个合法结果。
- 最后一席多人同时申请只有一人成功，人数不超过容量。
- 伪造/错账号/错环境 Apple 交易不能开通；退款和旧 webhook 不复活权益。
- 拉黑/封禁/删号最终提交时重新检查；缓存/旧链接/付费不能绕过。
- 媒体跨账号绑定、损坏、伪装格式、超限、EXIF、孤立对象都要测试。
- 断网、迟到响应、服务重启、时间边界/DST、恢复备份不能制造数据丢失或重复。

收到后端明确授权后的建议顺序（建议，不是已批准选型）：
先确认一期范围与状态机 → 契约/schema/隔离测试库 → 先写能失败的集成测试 →
认证/资料/媒体基础 → 发现/匹配/聊天/邀约真实多人闭环 → 所选扩展与支付 →
故障/性能/真机/审核发布验收。安全和隐私随模块实施，不最后补。
BE 的数据库、并发和 HTTP 权限测试必须访问真实隔离服务与数据库；
现有内存 reference tests 不能替代。Apple 要分别报告 verifier fixture
集成测试与真实 Sandbox 证据。

7. 架构与代码边界
=================
现有栈：静态 HTML + CSS + 原生 JavaScript ES Modules，无 React/Vite 构建。
Python 仅用于本地静态 HTTP；Playwright 是开发测试依赖，不是线上服务。
不要为交接擅自换框架或大规模重写；需要迁移时单独提案、说明收益和回滚。

模块地图：
index.html          初始页面、启动壳、静态发现卡、adapter 选择与入口资源版本。
app.js              组合、导航、发现交互、语言应用；逐步避免继续堆业务职责。
features/onboarding  注册/登录 UI、恢复 session、启动 gate。
features/launch_assets 首图/纹理/字体准备、失败和超时释放。
features/account     Me、编辑/预览、设置/隐私/注销的现有 UI。
features/chat        Chat/Profile 与聊天内邀约 UI（持久业务待接入）。
features/moments     已连接动态、作者跳转、评论/发布 UI。
features/membership  Plus、账单、陌生直邀；membership_copy 为其文案。
features/train       公开活动页、类别/详情/参加/主持 UI；activity_seed 仅演示。

pace_repository.mjs  统一数据接口，本地 adapter 与 HTTP adapter。
api_client.mjs       /api/v1 路径、请求参数/JSON/错误/凭据边界。
app_logic / connection_feed / sport_catalog / engagement_service
                    纯规则、目录、内存参考服务；不能依赖 DOM 或浏览器网络。

依赖方向：UI → repository → HTTP adapter/API client → 未来服务端。
纯领域规则可被调用，不能反过来依赖 UI。网络请求不要散进各 feature。
新增业务字段先定义输入、公开输出、角色权限、状态转换、失败与幂等契约。
中文名称不当主键；统一 user/profile/match/conversation ID；服务端决定 actor。
本地 adapter 用可重复 seed；HTTP 失败必须真实错误，不能回退假数据。
不要只改一条邀约路径，把聊天内和陌生直邀规则拆成互相矛盾的两套。

样式级联：styles.css 负责字体和显式 imports：
base → discovery → activity → onboarding → conversation → train → membership。
样式归属对应 feature 文件；避免往全局末尾无限追加补丁或提高 specificity。
当前有历史覆盖层，修改前读最终生效规则；清理单独做、用截图证明无回退。
相同资源 cache stamp 要在 HTML、所有生产 imports、CSS 和相关 fixture 一致；
contract tests 会检查，不可只改一处。新增模块补 package check 和依赖约束。

8. 安全与数据质量规范（上线验收要求，不表示已经实现）
=================================================
- 服务端才是身份、会员、匹配、验证、作者、主持、人数和公开字段的权威。
  每条 mutation 做认证、资源级授权、输入 schema 校验和最终状态检查。
- Web 使用安全会话策略，Cookie 的 HttpOnly/Secure/SameSite、CSRF、过期、
  撤销需一起设计；原生长期凭据放系统安全存储，密码/token 不放 localStorage。
- UI 输出不可信文本用 textContent 或集中转义；URL 单独验证协议/归属；
  不能因为 HTML 已转义就认为上传、外链、脚本注入都已安全。
- 原子事务和数据库约束守住 match 唯一、消息/交易幂等、名额和关系权限。
  不以单进程内存锁或按钮 disabled 代替服务端并发正确性。
- 密钥放环境密钥库，Git 中只可放空值/假值 .env.example；不提交 .env、
  Apple .p8、证书/私钥、生产数据库、用户媒体、聊天内容或带 token 的日志。
- 日志保留 request ID/错误码/必要状态，过滤密码、session、完整 JWS、私聊
  与精确位置；错误回给用户可理解、可重试，不暴露内部堆栈和账号枚举信息。
- 上传验证真实内容/大小/尺寸/数量/归属，剥离敏感元数据，审核和清理可追踪。
- 举报/拉黑/取消匹配、运营联系与处理闭环属于交友产品基础安全能力。
- 所需数据最少化；隐藏字段在各读取入口都一致；删号包含派生缓存和异步任务。
- 依赖变更用锁文件、审阅来源和许可；进行漏洞扫描并逐项判定，不盲目强制升级。
- 生产需隔离环境、HTTPS、最小权限、监控告警、备份恢复演练和回滚流程。
- 官方平台规则会变；确认目标市场后复核 Apple 登录/订阅/隐私/UGC/删号要求：
  https://developer.apple.com/app-store/review/guidelines/
  真实购买、真机、TestFlight、商店信息与运营验收未完成前不可声称可上线。
